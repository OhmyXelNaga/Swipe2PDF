# Swipe2PDF

개인용 Android 화면 캡처·스와이프·PDF 변환 시제품입니다. 첫 화면을 캡처한 뒤 접근성 서비스의 오른쪽→왼쪽 제스처를 실행하며, 같은 정규화 자르기 영역을 모든 이미지에 적용합니다. 서버, 로그인, 광고, 분석, 클라우드 동기화는 사용하지 않습니다.

## 요구 환경

- Android 12(API 31) 이상
- Android Studio 또는 JDK 17 + Android SDK 35 + Gradle 8.11.1
- 실제 화면 캡처와 접근성 동작 검증용 Android 기기

외부 라이브러리는 AndroidX Compose, DataStore, Lifecycle, Kotlin Coroutines만 사용합니다. UI, 설정 저장, 서비스 생명주기와 비동기 처리를 위한 공식 Android/Kotlin 구성요소입니다. 이미지·PDF 처리에는 Android 공식 API를 사용합니다.

## 빌드

프로젝트 루트에서 다음을 실행합니다.

```bash
./gradlew testDebugUnitTest assembleDebug
```

APK 출력 위치는 `app/build/outputs/apk/debug/app-debug.apk`입니다.

## APK 설치

1. 기기에서 **설정 → 보안 및 개인정보 보호 → 출처를 알 수 없는 앱 설치**로 이동합니다.
2. APK를 여는 파일 관리자 또는 브라우저에 설치 권한을 허용합니다.
3. `app-debug.apk`를 열고 **설치**를 누릅니다.
4. USB 디버깅을 사용한다면 `adb install -r app/build/outputs/apk/debug/app-debug.apk`로 설치할 수도 있습니다.

## 권한 설정

앱의 **권한** 화면에서 각 상태를 확인합니다.

1. **접근성 서비스**: 설정을 열어 Swipe2PDF를 켭니다. `dispatchGesture()`로 오른쪽에서 왼쪽 스와이프를 수행하는 데만 사용합니다.
2. **화면 캡처 동의**: Android 시스템 창에서 허용합니다. Android 버전에 따라 작업마다 다시 동의해야 합니다.
3. **알림**: 캡처 중 포그라운드 서비스 알림 표시를 허용합니다.
4. **다른 앱 위에 표시**: 대상 앱 위에서 플로팅 컨트롤러를 표시하기 위해 허용합니다.

Swipe2PDF는 DRM, `FLAG_SECURE`, 보안 화면을 우회하지 않습니다. 대상 앱이 캡처를 막으면 검은 화면이나 이용 불가 이미지가 나올 수 있습니다.

## 사용 방법

1. 필요한 권한 네 가지를 모두 준비합니다.
2. **작업 설정**에서 총 페이지, 제스처 위치·시간, 전환 대기, 공통 자르기 영역, 파일 이름을 지정합니다.
3. **플로팅 컨트롤러 켜기**를 누르고 대상 앱으로 이동합니다.
4. 첫 화면부터 촬영됩니다. 일시정지·재개·중지는 플로팅 컨트롤러에서 실행합니다.
5. 촬영 후 앱의 **결과 검토**에서 순서 변경, 삭제, 유사 이미지 경고를 확인합니다.
6. **PDF 만들기**를 누릅니다. 파일은 `다운로드/Swipe2PDF/`에 저장되며 기존 이름이 있으면 `(2)`, `(3)`이 붙습니다.

## 실제 기기 시험 체크리스트

- [ ] Android 12 이상에서 APK 설치 및 앱 실행
- [ ] 접근성 서비스를 끄면 작업이 시작되지 않고 한국어 안내가 표시됨
- [ ] 화면 캡처 거부 시 한국어 오류가 표시됨
- [ ] 알림·오버레이 권한 상태가 앱 복귀 후 갱신됨
- [ ] 1페이지 작업이 1회 캡처·0회 스와이프로 끝남
- [ ] 10페이지 작업이 첫 페이지 선캡처, 정확히 10회 캡처·9회 스와이프로 끝남
- [ ] 손가락 이동이 화면 너비 85%에서 15% 방향임
- [ ] 마지막 캡처 뒤 추가 스와이프가 없음
- [ ] 빠른 반복 입력으로 중복 작업이 생성되지 않음
- [ ] 일시정지 중 캡처/스와이프가 진행되지 않고 재개 후 한 루프만 진행됨
- [ ] 중지하면 기존 촬영본이 결과 검토에 남음
- [ ] 캡처 직전 컨트롤러가 사라지고 이미지에 포함되지 않음
- [ ] 컨트롤러를 가장자리로 이동할 수 있음
- [ ] Fold 기기를 접거나 펼치거나 회전하면 작업이 중단되고 기존 이미지가 남음
- [ ] 상태바·내비게이션바를 제외한 공통 자르기가 모든 이미지에 동일하게 적용됨
- [ ] 삭제·앞으로·뒤로 조작 결과가 PDF 페이지 순서와 일치함
- [ ] 유사한 연속 이미지에 경고가 표시되며 자동 삭제되지 않음
- [ ] 한글 파일명이 정상 저장되고 같은 이름은 자동 증가함
- [ ] PDF 열기·공유·저장 위치 보기 동작
- [ ] 캡처·중지·오류 후 포그라운드 알림과 오버레이가 남지 않음
- [ ] 보호된 앱 화면을 우회하지 않고 안내함

## 구현 범위와 알려진 제한

- 세로 화면을 우선한 시제품이며 좌표와 자르기는 실제 화면 크기에 대한 비율로 계산합니다.
- 접기·펼치기·회전·표시 크기 변경 시 기존 세션을 계속 쓰지 않고 안전하게 중단합니다.
- Android 시스템 또는 제조사 절전 정책이 서비스를 강제 종료할 수 있습니다.
- MediaProjection 동의 재사용 가능 범위는 Android 버전에 따라 다르므로 새 작업에서 재동의를 요구할 수 있습니다.
- 전체 해상도 PNG는 저장 공간을 많이 사용합니다. PDF 페이지 렌더링은 메모리 안전을 위해 긴 변을 최대 2000px로 제한합니다.
- 접근성, MediaProjection, 오버레이, Fold 상태 변화는 JVM 단위 테스트만으로 검증할 수 없어 실제 기기 시험이 필요합니다.
